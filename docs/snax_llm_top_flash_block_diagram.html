snax_llm_top_flash — integrated block diagram

20-master top: host CSR/DMA, CSR + sequencer control mux, 16-lane K/V streamer, Q/act streamer, FP4/FP16 write-out, V transpose + log-quantizer path, fused FP4 core, 32-bank TCDM.

Top-level notes

  • P0 FP4 backpressure missing: u_fp4_skid.ready is not connected; core/SLQ has no out_vec_fp4_ready_i. A full skid drops packets.
  • P0 FP16 backpressure missing: write_out.core_out_fp16_ready_o and v_quant_path.core_out_fp16_ready_o are unconnected; core has no out_vec_fp16_ready_i. FP16 write-out takes 4 cycles/vector; V path only accepts in GATHER.
  • P0 Done/busy: sequencer mode busy = seq | v, done = seq_done | v_done; wo_busy and fp4_skid_valid are not included, so the host can read OUT early.
  • P0 WT streamer credit: snax_streamer_wt_16ch lacks the outstanding-read credit that act_bcast has; DRAIN only waits for skid empty.
  • P1 Sequencer: QK_ACT_DRAIN hardcodes 2 K-blocks (kb < 1) instead of K_BLOCKS-1; p_fifo_almost_full and l_ready are not used.
  • P1 V path: gathers 16 tokens, while M_Q=8; it needs 2 query tiles or a batch/ready protocol. v_start is CSR-only, not sequenced.
  • P1 Legacy tops: snax_llm_top + snax_llm_shell are 18-master, static-address, no V path; do not use as the integrated top.
  • Compile: new top 0 errors / 16 warnings; core TB 0 errors / 7 warnings. vsim currently exits before log even for the known-good skid TB — environment/license issue, not RTL mismatch.
